# 오전·오후 브리핑 구현 범위

승인: 현재 bullet 표현 유지, 원래 섹션 복원, 오전/오후 실행 구현, 필요한 MCP와 원격 반영.

1. MCP: 공개 FRED CSV 금리·원유, SQLite 관측 버전·고정 snapshot, 변화와 이례성, PNG, SEC/DART 공시, bounded read tools. 기존 심리 도구 유지.
2. Yummy: AM/PM 회차, 입력 cutoff·실패 복구, 오전 snapshot/차트, 오후 관심기업과 원문 후보, 새 트렌드·업종 뉴스 섹션, 발행 원고 멱등 재사용.
3. Telegram: /watch 관리, /history, /brief am|pm, 차트 전송·실제 전송 시각·불확실 상태 보존.
4. 검증: 날짜/수정치/결측·계산·수집 실패, AM/PM/주말, 내용 섹션, 중복 전송, 원문 비밀 제외. 실제 외부 수집과 AM/PM 미발행 결과 검토.
5. 배포: 실행 파일 백업, 서비스 재시작, 로드 설정 확인. MCP 저장소 feature 브랜치에 변경 commit/push 후 원격 커밋 확인. runtime는 기존 로컬 운영 디렉터리에 유지하고 연동 계약 문서 제공.

현재 없는 입력: 관심기업 목록, DART 키, SEC 식별 User-Agent. 무자료/미설정 상태로 동작시키며 임의 기업·수치를 만들지 않는다.

설계 문서 전체의 전용 사건 그래프·벡터 검색은 이번 배포의 선행조건이 아니다. 원문 기반 주제 검색과 발행 이력으로 연결하고 구현 한계를 기록한다.
