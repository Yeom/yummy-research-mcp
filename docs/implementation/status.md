## 인접 운영 프로그램 연동

`../yummy_research/yummy_codex/editions.py`가 MCP 수집 CLI를 호출한다.
AM은 지표 수집·기계 계산 숫자·차트, PM은 사용자 등록 관심기업 뉴스 발견 자료를 제공한다.
두 판 모두 핵심 흐름·새 트렌드·업종별 뉴스·다음 확인을 유지한다.
등록 기업 목록은 Telegram /watch와 로컬 운영 DB에서 관리한다.
사용자 관심 이유는 미입력으로 남기며 모델이 투자 의도를 추정하지 않는다.

Telegram `/watch`, `/watch add 기업명 | 테마`, `/watch remove 기업명`,
`/brief am`, `/brief pm`, `/history`를 지원한다.
본문과 차트는 별도 전송 상태를 저장하고 불확실한 전송은 자동 재시도하지 않는다.
런타임 SQLite에는 watchlist와 deliveries.sent_at이 추가된다.
기존 이력의 정확한 발행시각은 추정해 채우지 않는다.

## 시각과 기억의 현재 수준

기존 LaunchAgent는 월~금 07:50/17:50, 토요일 07:50에 **생성을 시작**한다.
실제 도착은 수집·모델 분석 시간만큼 늦을 수 있다. 정각 도착을 위한 사전 생성 큐는 후속 범위다.
AM은 직전 예정 브리핑 시각부터, PM은 당일 07:50부터 원문을 선별한다.
성공한 마지막 브리핑이 더 오래되면 최대 7일 내에서 미처리 구간을 포함한다.
월요일 오전은 토요일 오전 이후를 포함한다. 관심기업 검색은 직전 평일 PM부터다.
모바일 수동 실행은 실행 시각까지의 자료로 생성한다.

운영 프로그램에 별도 research_memory.db를 추가했다. 원문·사건/해석 버전, FTS5·별칭·제안 관계 검색, 반대 근거와 회차별 참조를 보관한다.
개인 기억은 이 시장 데이터 MCP에 노출하지 않는다. 역사 자료의 모델 전송은 운영 설정의 별도 승인 범위로 제한한다.
전용 그래프 DB·외부 임베딩·자동 인과 검증은 도입하지 않았다. 인용/참조 검사만으로 원문의 진실성을 확정하지 않는다.
상세 구현 안내는 인접 운영 프로젝트의 docs/design/04-memory-implementation.md에 있다.

DART 키·SEC User-Agent가 없으면 공시 도구는 미설정 상태다.
현재 PM 자동 수집은 뉴스 검색과 Telegram을 사용하며 공시 전수 감시는 아니다.
